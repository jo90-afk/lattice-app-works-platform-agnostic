# Experience Lead Expertise

## Decision model

- Design from observed user context through evaluation, not from visual composition alone.
- Model every observable state: initial, empty, loading, partial, error, recovery, permission, interruption, offline, destructive confirmation, success, and return/re-entry.
- Use native semantics and established platform patterns. Preserve user control, clear feedback, reversible actions, and consistent mental models.
- Treat accessibility as a design input. Define keyboard/focus behavior, names/roles/states, reading and navigation order, contrast, text resize/reflow, target size, motion alternatives, errors, captions, and assistive-technology behavior.
- Minimize cognitive load with plain language, chunking, recognition over recall, forgiving input, and clear next actions.

## Operating checks

1. Confirm users, contexts, constraints, risks, and linked product behavior.
2. Map the complete journey and exceptional states before polishing a screen.
3. Specify semantic structure, interaction, content, responsive/adaptive behavior, and recovery.
4. Evaluate with representative users and accessibility methods appropriate to consequence.
5. Record observations as evidence; revise consequential truths instead of burying them in design files.

## Evidence expected

- State and journey coverage, content rationale, accessibility annotations, and platform-specific adaptations.
- Evaluation method, participants/context, findings, limitations, and the exact design decision affected.
- Testable acceptance behavior rather than subjective approval language.

## Failure patterns

Avoid happy-path-only designs, appearance as the sole specification, accessibility overlays, custom controls without semantics, dark patterns, and claims that one platform's convention is universal.

## Source basis

- [WCAG 2.2](https://www.w3.org/TR/WCAG22/) and [Understanding WCAG 2.2](https://www.w3.org/WAI/WCAG22/understanding/) — normative web accessibility criteria and current explanatory guidance.
- [WAI-ARIA Authoring Practices Guide](https://www.w3.org/WAI/ARIA/apg/) — accessible interaction patterns and keyboard models for web widgets.
- [W3C Cognitive Accessibility Guidance](https://www.w3.org/TR/coga-usable/) — usable content and interactions for cognitive and learning disabilities.
- [ISO 9241-210:2019](https://www.iso.org/standard/77520.html) — human-centred lifecycle guidance.
- [GOV.UK user research guidance](https://www.gov.uk/service-manual/user-research/how-user-research-improves-service-design) — research as evidence for service decisions.

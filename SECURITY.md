# Security Policy

## Reporting a vulnerability

Do not publish a security-sensitive issue, secret, personal-data exposure, or exploitable reproduction in a public issue or pull request.

For a private repository, use the repository’s private security-advisory feature when it is enabled, or contact the repository owner through the established private channel. Include the affected project ID, affected paths, reproducible behavior, impact, and any safe mitigation already taken.

## Repository hygiene

- Never commit API keys, tokens, private keys, signing material, credentials, or production exports.
- Keep sensitive project facts inside the minimum necessary private project capsule.
- Do not copy sensitive evidence into the portfolio registry or Agency Kernel.
- Treat external actions, destructive changes, material residual risk, and production launch as consequence boundaries governed by agency.yaml.

The security role and escalation policy are defined in agents/security.md and governance/autonomy-policy.md.
